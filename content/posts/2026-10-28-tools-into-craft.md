我师父——如果修自行车的老周算师父的话——有一块磨刀石，青灰色，中间已经磨出一个浅浅的凹槽。他磨剪刀的时候不说话，手腕的角度几乎不变，水从石头上流下来，带着一点铁腥味。磨完他会用拇指横着刮一下刃口，然后点点头或者摇摇头。

那个点头，是我见过最像「判断」的动作。

## 生成变便宜了，判断没有

这两年做开发，最明显的变化是：从零写出一段能跑的代码，几乎不再是成本。你描述清楚，它就来了。来得又快又体面，语法正确，命名合理，甚至附上注释。

但事情的总量没有减少，只是重心移了位置。以前七成时间在敲，三成时间在想；现在两成时间在敲，八成时间在挑——挑哪一版该留、哪一种抽象会在一周后反咬你、这个「优雅」是不是只是把复杂度挪到了看不见的地方。

我做过一个实验：让工具生成一个日期区间合并函数，它给了四十行，逻辑正确，边界也考虑了大半。我最后交出去的是十二行。

差别不在长度，在这几件事：

- 它把「同一天」判成了空区间，而业务里同一天意味着「这一天」；
- 它用了一串嵌套的三元表达式，读的人要在脑子里跑一遍解释器；
- 它没有留下任何关于「为什么这样合并」的痕迹。

第三点最要紧。**能跑的代码是工具给的，能改的代码得自己写。**

```js
// 合并重叠区间：闭区间语义，端点相接视为重叠
const merge = (ranges) =>
  ranges
    .sort((a, b) => a[0] - b[0])
    .reduce((acc, [s, e]) => {
      const last = acc[acc.length - 1];
      if (last && s <= last[1]) last[1] = Math.max(last[1], e);
      else acc.push([s, e]);
      return acc;
    }, []);
```

这十二行里，真正属于我的只有两处：闭区间的选择，和那句注释。剩下的是公共知识。但一个函数的价值，往往就压在那两处上。

## 手艺是「多余的」那部分

磨刀石上的凹槽没有任何效率意义。机器磨一刀只要三秒，老周要三分钟。但他能从刃口的手感判断钢材有没有暗伤——这是三秒里得不到的信息。

我把这类东西叫「多余的部分」：为了理解而多做的那一遍，为了确认而重写的那一次，为了以后能改而多留的一句注释。它们在当次的产出里是亏损的，在长期的维护里是盈利的。

有意思的是，工具越强，「多余的部分」越贵。因为它是唯一无法被外包给生成器的环节——它依赖你对自己处境的了解，而这件事没人替你持有。

> 工具解决「能不能」，手艺回答「该不该」。前者正在归零，后者正在涨价。

## 三个不难做到的动作

我不太相信「手艺人精神」这种说法，太隆重了。落到实处，是三个很小的动作：

1. **每个交付物留一处手工痕迹。** 一句只有你会写的注释，一个只有这个场景才成立的处理。不是炫技，是给自己留一个入口，让三个月后的你还认得出这是自己做的。
2. **每周重读一次自己上周写的东西。** 手艺的敌人不是不会，是忘了自己当初为什么这么想。重读是最便宜的复盘。
3. **保留一件与产出无关的手工。** 磨刀、抄经、削木头、手冲咖啡。它的作用是校准你对「做得好」的体感，别让这个体感被「能跑就行」悄悄替换掉。

老周去年把铺子关了，磨刀石留给了我。我一直没舍得用，凹槽还是那个形状。

有时候我觉得，我们这代人面对的问题不是「会不会被替代」，而是「还愿不愿意多磨那三分钟」。愿意的人不会失业，只会变慢——而慢，恰恰是手艺的定价方式。
